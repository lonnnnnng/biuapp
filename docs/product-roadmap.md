# BiuApp 后续推进线路图

规划日期：2026-08-08
适用仓库：`android-app`
维护边界：`desktop-app` 仅作只读对照，不修改、不提交

## 1. 产品定位

BiuApp 是一款便携的 Bilibili 听歌软件，主要收听已关注或手动添加的 UP 主发布的歌曲投稿和视频合集。

- 默认进入音频播放模式；视频是当前歌曲的手动补充模式。
- 主链路是：**管理 UP 主来源 → 发现歌曲 → 曲目级整理 → 连续收听 → 离线收听**。
- 多 P 视频按 `bvid + cid` 识别为独立曲目；播放、歌词、历史、下载和歌单都不能只使用主视频 ID。
- 后续优先提升听歌效率和播放稳定性，不扩张为完整 Bilibili 社区客户端。

### P1：增强发现与播放体验

仅在 P0 收口后推进，任何改动不得破坏后台播放、锁屏控制、队列恢复和下载恢复。

- [ ] 低功耗音频频谱：默认关闭或可关闭，观察耗电、掉帧和后台影响。
- [ ] 视频模式画中画：只针对视频播放评估，不申请音频悬浮窗权限。
- [ ] 非视频动态（图文、转发等）：先确认接口稳定性、展示价值和账号权限，再决定是否纳入主导航。
- [ ] 真实三连扣币：必须取得明确授权后再做不可逆真机验收；保留现有确认弹窗、风控提示和失败回滚。
- [ ] M18 只接受回归修复，不新增第二套播放状态或重复队列模型。

### P2：个性化与平台增强

- [ ] 自定义强调色、背景色、圆角和字体家族，并建立亮暗主题对比度门槛。
- [ ] 菜单显示/隐藏配置，避免在小屏和大字号下入口拥挤。
- [ ] 自定义音频/视频下载目录、空间占用统计、清理入口和封面下载。
- [ ] 有明确驾车需求后再评估 Android Auto 媒体浏览与语音控制。
- [ ] 播放磁盘缓存暂不引入；只有容量上限、清理入口、稳定 cache key 与永久下载边界同时明确后重新评估。

## 4. 明确不做或不优先

- 不恢复“稍后再看”页面入口。
- 不恢复手动高/中/低音质档位；继续默认最高可用音质并自动降级。
- 不把评论、私信、图文社区浏览等完整社区能力作为主线。
- 不做设置导入/导出。
- 不恢复 Bilibili 字幕接口作为歌词来源。
- 不优先投入应用内代理、悬浮窗权限和纯装饰动画。

## 5. 每个切片的交付门槛

1. 先完成用户可操作的纵向链路，再补充横向优化；不得只提交孤立 UI 或 API。
2. 固定运行：
   ```text
   ./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
   ```
3. 涉及播放、下载、账号和歌词时，必须使用真实链路验收；JVM 测试不能替代真机验收。
4. 真机优先使用 Redmi `wsvwypiz7xwslvl7`；未经明确许可不切换到其他设备或模拟器。
5. 记录 UI、Room 迁移、通知、后台服务、网络恢复和 `logcat -b crash` 结果，并区分已验证与待验证结论。
6. 每完成一个阶段，同步本文件、`development-roadmap.md`、`feature-migration-matrix.md` 和 `desktop-android-feature-gap-audit.md`。
7. 只修改和提交 `android-app`，提交说明使用中文；用户未明确要求时不推送、不发版。

## 6. 下一轮冻结清单

1. M15-M19 进入回归维护，不再新增第二套来源、队列、下载索引或歌词状态模型。
2. M20 只先做价值和风险评估；视频画中画、低功耗频谱、存储空间统计与自定义下载目录必须逐项获得明确收益后再立项。
3. M14 正式版质量继续作为横向门槛，优先补崩溃、耗电、后台限制、隐私、签名和发布流水线专项验证。
4. 后续仍只修改 Android 仓库，桌面端保持只读；每个独立切片使用中文提交并同步四份路线/审计文档。
