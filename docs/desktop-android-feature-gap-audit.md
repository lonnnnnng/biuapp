# 桌面端与 Android 端功能差异审计

## 审计基准

- 审计日期：2026-08-08
- Git 分支：`main`
- Android 版本：`0.1.18` 工作树，包含 M11-M17 及 M18 首页聚合、统一搜索、快捷队列、拖动/批量编辑、睡眠定时和统一历史纵向切片
- 桌面端参考基线：`../desktop-app` 的 `7d49920`
- 审计范围：桌面端 `../desktop-app/src/` 与 Android 端当前仓库的代码
- 审计方式：只核对当前代码，不以早期迁移矩阵或开发计划中的状态作为最终依据

## 总体结论

Android 端的“找歌 -> 用户/空间发现 -> 关注视频动态 -> 单 P/多 P 音视频播放 -> 播放模式和倍速 -> 队列编辑 -> 后台和锁屏控制 -> 下载 -> 状态恢复”主链路已经比较完整；当前主要缺口集中在歌词高级调整、失效合集条目处理和更深的外观个性化，暂时不能算功能完全对齐。

当前 Android 端包含“推荐”“动态”和“音乐库”三个主页面。音乐库包含收藏夹、统一历史、本地歌单、本地音乐和下载；历史页内部按全部/在线/本地来源筛选。

## 已经基本对齐

- Bilibili H5 登录与账号状态识别。
- 综合热门、每周必看、全站排行、入站必刷和自选 UP 首页；配置来源后支持最新发布、未播放、最近播放，并可按全部、本地分组或单个 UP 筛选和连续加载。
- 统一搜索视频、UP 主、已配置首页来源的系列/合集和本地歌单；视频支持综合/最新排序，视频与 UP 主支持分页，最近 10 条关键词可跨冷启动恢复。
- 单 P、多 P、音频/视频手动切换、竖屏视频小窗、自动旋转横屏沉浸播放、进度拖动、实际轨画质切换和播放列表选择。
- 顺序播放、列表循环、随机播放、单曲循环及七档倍速，设置可跨进程恢复。
- 播放队列支持设为下一首、上下移动、长按拖动、单项/批量移除、清空和保存为本地歌单，编辑后的队列可跨进程恢复。
- 后台播放、锁屏/通知栏/耳机控制、进程重启后的队列恢复。
- “我创建的”“我收藏的”、普通收藏夹和视频合集浏览、收藏夹管理及视频加入/移出。
- 统一历史入口：在线分页、搜索、单条删除、全部/在线/本地来源筛选、明确范围清空和 Bilibili 播放进度上报开关。
- LRCLIB 手动歌词搜索、时间轴展示、当前行跟随和 Room 缓存。
- 亮色、暗色、跟随系统主题及系统栏同步。
- 本地音乐和本地播放历史；本地歌曲起播前可选择仅此曲或当前目录，并显示实际入队数量。
- 单曲及收藏夹批量音频/视频下载、断点恢复和网络限制。
- 应用内检查更新、下载和安装新版本。
- UP 主名称搜索、空间资料、投稿分页、独立关注列表以及关注/取消关注已完成 Redmi 真实账号验收。
- 关注视频动态支持下拉刷新、真实账号游标分页、直接播放、点赞/取消点赞和带确认的一键三连；Redmi 已完成点赞往返验收，真实三连扣币尚未执行。

## 稍后再看说明

Android 仓库仍保留读取稍后再看的 API 方法 `BilibiliRepository.watchLater()`，但当前页面没有入口，也没有删除操作。

这符合此前从 Android 账号页删除“稍后再看”的产品决策，但从桌面功能对齐角度仍属于未实现。

2026-07-31 已确认继续保持 Android 端不提供稍后再看入口；API 方法暂时保留供兼容和后续评估使用，迁移矩阵与路线图不再将其标记为已完成能力。

## 不需要机械迁移的平台功能

以下桌面能力不建议按原形式迁移：

- 系统托盘：Android 使用媒体通知和锁屏媒体控件替代。
- 桌面窗口最小化和关闭行为：由 Android Activity 生命周期和系统返回栈替代。
- 桌面全局快捷键：由通知栏、锁屏、耳机和蓝牙媒体按键替代。
- 桌面音量滑块：Android 优先使用系统媒体音量控制。
- Electron 独立 mini 窗口：Android 已有应用内底部迷你播放栏；是否增加画中画或悬浮窗需要单独评估权限和使用价值。
